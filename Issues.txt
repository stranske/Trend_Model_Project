1. Use Workflows Anthropic secret alias (CLAUDE_API_STRANSKE) for Streamlit LLM configuration

## Why

The Workflows automation system standardizes on `CLAUDE_API_STRANSKE` for Anthropic credentials. Trend Model Project should align on the same canonical variable to avoid duplicated secrets and inconsistent environment setups across repos.

## Scope

Make `CLAUDE_API_STRANSKE` the canonical Anthropic API key input for Trend’s LLM configuration (Streamlit + supporting helpers). Optionally allow `ANTHROPIC_API_KEY` as a backward-compatible fallback (recommended).

## Non-Goals

This does not change which providers are supported (still OpenAI / Anthropic / Ollama).
This does not store or display secret values in the UI.
This does not introduce new secret-management mechanisms.

## Tasks

- [ ] Update Streamlit LLM settings resolution to treat `CLAUDE_API_STRANSKE` as the primary env var when provider is `anthropic`.
- [ ] (Optional but recommended) Keep `ANTHROPIC_API_KEY` as a fallback if `CLAUDE_API_STRANSKE` is unset, and document the precedence order.
- [ ] Ensure all Streamlit components that resolve provider keys (config chat, explain results, comparison LLM, replay tooling) consistently use the shared resolver logic (no one-off env reads that bypass precedence).
- [ ] Add unit tests confirming Anthropic config resolves when only `CLAUDE_API_STRANSKE` is set (and also when only the fallback is set, if the fallback is kept).
- [ ] Update docs to state the canonical Anthropic variable name and the precedence rules.

## Acceptance Criteria

- [ ] With `CLAUDE_API_STRANSKE` set and no `ANTHROPIC_API_KEY`, selecting provider `anthropic` works without “Missing API key” errors.
- [ ] If fallback is enabled: with only `ANTHROPIC_API_KEY` set, selecting provider `anthropic` still works.
- [ ] No Streamlit component uses a different Anthropic key precedence than the shared resolver (verified via tests or a simple grep + review).
- [ ] Documentation explicitly states the canonical variable and any fallback behavior.

## Implementation Notes

Primary files to check/update:
- `streamlit_app/components/llm_settings.py` (canonicalize Anthropic key resolution)
- `streamlit_app/pages/2_Model.py` (provider config resolution should defer to shared resolver)
- `streamlit_app/components/explain_results.py` (ensure it relies on shared resolver behavior)
- Any other LLM-enabled components under `streamlit_app/components/`

Proposed precedence for anthropic:
1. `TS_STREAMLIT_API_KEY` / `TREND_LLM_API_KEY` (if you want provider-agnostic “app key”)
2. `CLAUDE_API_STRANSKE` (canonical anthropic key)
3. (Optional) `ANTHROPIC_API_KEY` fallback for compatibility
