1. [Streamlit NL] Cache LLM + ConfigPatchChain instances to reduce config-chat latency
labels: [agent:codex, enhancement]
## Why

The Streamlit config chat constructs a new LLM client and chain during preview generation, which adds latency and variability across calls. Caching chain construction per session should improve UX.

## Scope

Cache creation of the LLM client and ConfigPatchChain used by `streamlit_app/pages/2_Model.py` while preserving env override behavior.

## Non-Goals

This does not change the ConfigPatch schema or patch semantics.
This does not store API keys in session state.

## Tasks

- [ ] Refactor `_build_nl_chain` in `streamlit_app/pages/2_Model.py` to use a cache mechanism appropriate for Streamlit (st.cache_resource or equivalent), keyed by provider/model/temperature.
- [ ] Ensure cache invalidation occurs when relevant settings change (provider, model, base_url, org, temperature).
- [ ] Add lightweight timing instrumentation for preview generation to verify chain reuse.

## Acceptance Criteria

- [ ] Repeated Preview operations in the same session reuse the cached chain (measurable via instrumentation/logging).
- [ ] Changing provider/model settings results in a new cached instance (no stale reuse).
- [ ] Existing config chat behavior remains correct (preview/apply/run still works).

## Implementation Notes

Primary file:
`streamlit_app/pages/2_Model.py`

5. [LLM] Optional structured-output mode for ConfigPatchChain (reduce parse retries and ambiguity)
labels: [agent:codex, enhancement]
## Why

ConfigPatchChain parses free-form model output into a ConfigPatch with retries. Adding an optional structured-output path (where supported) should reduce retries and improve determinism.

## Scope

Implement an optional structured-output mode in ConfigPatchChain invocation that requests strictly valid JSON for ConfigPatch and uses a single repair retry on validation failure.

## Non-Goals

This does not change the patch schema.
This does not require all providers to support structured output (fallback remains supported).

## Tasks

- [ ] Add a structured-output execution path in ConfigPatchChain._invoke_llm that prefers strict JSON output when supported by the provider/client.
- [ ] Implement a single repair retry that includes validation error details when structured parsing fails.
- [ ] Add tests covering: valid structured output, malformed JSON output that repairs successfully, and fallback behavior when structured output is unavailable.

## Acceptance Criteria

- [ ] Structured-output mode produces valid ConfigPatch objects with fewer retries (test-covered via deterministic fixtures).
- [ ] On malformed outputs, exactly one repair retry is performed.
- [ ] Fallback parsing behavior still works for providers that cannot do structured output.

## Implementation Notes

Primary file:
`src/trend_analysis/llm/chain.py`


6. [New capability] What-if batch runner - generate and compare multiple config variants from one instruction
labels: [agent:codex, enhancement]
## Why

Config chat is great for single edits, but real decision-making often involves comparing a few plausible variants (conservative/baseline/aggressive). Automating variant generation and comparison extends the app’s practical capacity.

## Scope

Add a What-if (3 variants) feature that takes one instruction, generates up to 3 config variants (via patches), runs analysis for each, and shows a comparison table with an optional export.

## Non-Goals

This does not run large hyperparameter searches.
This does not change the underlying analytics engine.

## Tasks

- [ ] Implement a helper that generates N=3 config patches from one instruction with explicit variant labels.
- [ ] Apply patches to a base config and run analysis for each variant with clear progress UI.
- [ ] Display a comparison table of key metrics and provide a download option for the comparison output.

## Acceptance Criteria

- [ ] The UI generates three labeled variants and successfully runs analysis for each.
- [ ] The comparison view shows consistent, clearly labeled metrics per variant.
- [ ] The feature enforces sane limits (N fixed/capped; clear errors for missing data).

## Implementation Notes

Likely touch points:
`streamlit_app/pages/2_Model.py`
`streamlit_app/components/analysis_runner.py`
`src/trend_analysis/llm/chain.py`
