⚖ Competing approaches — factors for the choice

1. run_analysis.py / run_multi_analysis.py — refactor (mine A23) vs delete (theirs Issue 10)

Factors: Their review did the wiring check I didn't — they report these modules are not in [project.scripts], not imported in src/, and only referenced by tests. If that holds, delete > refactor (don't dedupe dead code). My "extract shared CLI skeleton" only applies if the modules are live. Decision rule: verify wiring first; delete if confirmed dead, otherwise apply my skeleton extraction. Lesson adopted: confirm a module is reachable before proposing to refactor it.

2. CLI helper dedup — "8 duplicates" vs "only 3 are real copies" (theirs Issue 9 + Appendix A)

Factors: Their Appendix A debunks an over-eager dedup: only _apply_trend_spec_preset, _apply_universe_mask, _attach_universe_paths are byte-equivalent; the other five are thin delegators and deduping them mechanically would break working code. Decision rule: dedupe only verified copies; leave delegators. Lesson adopted: my coarser dedup items (A7 harness, A22 cost-primitive) should be split into "verified copy → merge" vs "intentional indirection → leave."

3. Config validation — forbid unknown keys (mine A1) vs run Tier-2 in the bridge (theirs Issue 3)

Factors: These are complementary, not competing. A1 makes inert/unknown keys fail loudly (extra="forbid"); Issue 3 makes the Streamlit bridge actually run Tier-2 validation so vol_adjust/max_turnover/selection_mode are checked. Decision rule: do both — they close different halves of the same gap. Sequence behind tests (tightening validation may reject configs silently accepted today).

4. "Silent coercion" theme — bfill→ffill (theirs Issue 5) joins frequency→monthly & weighting→equal (mine A3/A6)

Factors: Three independent instances of the same anti-pattern (a config value silently mapped to something else with no error). Decision rule: adopt a project-wide policy — honor the value or reject it; never silently coerce — and fix all three under one banner. Their Issue 5 is the instance I missed.

5. Consumer-repo ownership (theirs Appendix B) — fix here vs upstream in stranske/Workflows

Factors: Their review flags that tools/*, .github/codex/*, and some scripts/langchain/* are synced from Workflows — fix upstream, not here. My audit scoped these out but didn't add the caveat. Decision rule: before filing any issue touching synced paths (e.g. their Issues 8 & 19), confirm ownership via the sync manifest. Lesson adopted: tag each issue with repo-vs-upstream ownership.

Relative proportions

My list: 37 issues — dominated by config/economic wiring (≈15), UX (6), methodology/feature epics (5), with fewer specific byte-level duplicates.

Forest vs trees — combine for the best dedup backlog.
